# Languages (i18n)

> Living doc — updated at ship (spec 014). The public site is available in French (default),
> English, Italian, Spanish and German; the back office is French only.

## What the visitor sees

- French at the usual URLs (`/`, `/collection`, `/parfums/tobacco`…). Other languages under
  their prefix: `/en`, `/it`, `/es`, `/de` (`/en/collection`, `/de/parfums/tobacco`…).
  `/fr/...` redirects to the bare French URL.
- A **FR / EN / IT / ES / DE** switcher in the header (desktop), the mobile menu, and the
  footer. It opens the same page in the chosen language.
- Product names, slugs and prices never change; scent family, mood, description and notes are
  translated. Prices are euros everywhere, in each language's notation (`195,00 €`,
  `€195.00`, `195,00 €`…).
- Stripe Checkout opens in the visitor's language and returns to the localized thank-you page.
- `<html lang>`, titles, descriptions, Open Graph locale and hreflang alternates follow the
  language.

## How it works

| Piece                       | Where                                                                                              |
| --------------------------- | -------------------------------------------------------------------------------------------------- |
| Locale list                 | `src/core/i18n/locales.ts`                                                                         |
| UI dictionaries             | `src/core/i18n/messages/{fr,en,it,es,de}.ts` (`fr` is the typed reference)                         |
| Locale on the server        | `getLocale()` in `src/core/i18n/server.ts` (root params)                                           |
| Locale in client components | `useI18n()` from `src/components/i18n/i18n-provider.tsx`                                           |
| URL helpers                 | `localizeHref`, `switchLocaleHref`, `pageAlternates` in `src/core/i18n`                            |
| Routing                     | `src/proxy.ts` (rewrite bare → `/fr`, redirect `/fr` → bare)                                       |
| Product translations        | `translations` jsonb on `fragrances`/`collections`; seed in `src/features/catalog/translations.ts` |
| Migration generator         | `node scripts/catalog-translations-sql.mjs`                                                        |

Decision record: [ADR 0007](../../architecture/decisions/0007-locale-routing.md).

## Adding a language

1. Add the code to `locales` and `ogLocales` in `src/core/i18n/locales.ts`, and its name to
   `locale.names` in every dictionary.
2. Add `src/core/i18n/messages/<code>.ts` typed as `Dictionary` and register it in `index.ts`.
3. Add the product copy under that code in `src/features/catalog/translations.ts`, regenerate
   the SQL with the script into a new migration, apply it.
4. Add the `formatEur` locale mapping in `src/lib/format.ts`.
5. Extend `e2e/i18n.spec.ts` with one assertion per language.

## Not yet

- All non-French copy is AI-drafted and awaits the client's review.

- Editing translations from the admin: the product form edits the French row only. Until phase 2,
  translations change through the seed file + migration.
- Browser-language detection: the visitor picks; no automatic redirect.
